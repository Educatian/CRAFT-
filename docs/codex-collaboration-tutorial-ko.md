# Codex 협업 튜토리얼

## Three.js 기반 PISA Globe를 SCORM과 Web App으로 만드는 전체 워크플로우

이 문서는 다음 목표를 위해 만들었다.

- Codex와 협업해서 인터랙티브 학습용 시각화를 만든다.
- 같은 결과물을 `SCORM 패키지`와 `일반 웹앱` 두 버전으로 관리한다.
- 프롬프트를 어떻게 쓰고, 어디서 검토하고, 어떤 식으로 피드백을 주면 되는지 단계별로 정리한다.
- 나중에 다른 주제의 시각화나 학습용 앱에도 그대로 재사용할 수 있게 한다.

이 문서는 실제로 다음 흐름을 거친 프로젝트를 바탕으로 정리했다.

- Three.js 기반 인터랙티브 3D PISA 지구본 시각화 제작
- SCORM 탑재용 버전 제작
- 클릭 횟수 트래킹 포함
- 영어 UI 전환
- 글로우 톤 조정
- 레이아웃 재설계
- multi-cycle PISA mock history 추가
- web deployment용 single HTML 버전 분리

---

## 1. 전체 그림

이 프로젝트에서 중요한 포인트는 이것이다.

1. 먼저 `무엇을 만들지`를 명확히 설명한다.
2. 그 다음 `어떤 형식으로 배포할지`를 정한다.
3. Codex에게 한 번에 다 시키지 말고, `단계별로 끊어서` 시킨다.
4. 시각화는 반드시 `브라우저에서 보고 피드백`한다.
5. SCORM 버전과 web 버전을 `같은 파일을 덮어쓰지 말고 분리`한다.

가장 중요한 원칙은 이거다.

`한 번에 완벽한 프롬프트를 쓰려 하지 말고, 설계 -> 초안 -> 시각 피드백 -> 세부 조정 -> 배포` 순서로 반복한다.

## 2. 추천 협업 방식

Codex와 작업할 때 가장 잘 되는 방식은 아래 순서다.

### 단계 A. 목표 정의

먼저 아래 네 가지를 말한다.

- 주제
- 인터랙션
- 데이터 구조
- 최종 배포 형식

예시:

```text
Three.js 기반 인터랙티브 3D 지구본 시각화를 만들어줘.
주제는 OECD PISA 상위 20개 국가의 학업 성취도 시각화.
국가별 reading, mathematics, science, composite score를 포함하고,
국가 간 유사성 네트워크를 보여주고 싶어.
최종 결과물은 SCORM 탑재 가능한 버전으로 만들고,
나중에 웹 배포용 단일 HTML 버전도 따로 뽑고 싶어.
```

### 단계 B. 기술 제약 명시

Codex는 기술 제약을 명확히 줄수록 결과가 안정적이다.

예시:

```text
기술 제약:
- Three.js r128 사용
- OrbitControls 없이 직접 pointer 이벤트로 회전
- 단일 HTML 파일
- 외부 라이브러리는 cdnjs, jsdelivr, unpkg만 사용
- 한국어 UI로 시작
- 나중에 영어 UI로 바꿀 수 있게 구조를 나눠줘
```

### 단계 C. 첫 버전 생성

첫 번째 프롬프트에서는 `완성도`보다 `작동하는 뼈대`를 우선한다.

예시:

```text
우선 작동하는 첫 버전을 만들어줘.
mock 데이터로 충분하고,
지구본, 국가 포인트, 연결선, 좌우 패널, 하단 타임라인이 모두 보이게 해줘.
시각적으로 너무 과한 연출보다 구조가 먼저 보이게 해줘.
```

### 단계 D. 브라우저에서 확인

이 단계가 매우 중요하다.

- 파일을 브라우저에서 연다
- 화면을 본다
- 이상한 점을 구체적으로 기록한다
- 그 내용을 다시 Codex에 전달한다

좋은 피드백 예시:

```text
타이틀이 너무 크고 중앙 뷰를 가린다.
좌측 패널과 우측 패널이 지구본 화면을 너무 많이 침범한다.
연결선 글로우가 너무 강하다.
나라 위치가 텍스처 기준으로 어긋나 보인다.
```

나쁜 피드백 예시:

```text
뭔가 이상함
별로 예쁘지 않음
```

Codex는 `막연한 취향`보다 `구체적인 레이아웃 문제`에 훨씬 잘 반응한다.

## 3. 추천 프롬프트 구조

실제로는 아래 6종 프롬프트만 잘 써도 대부분 해결된다.

### 3-1. 베이스 생성 프롬프트

```text
Three.js 기반 인터랙티브 3D 지구본 시각화를 만들어줘.

주제:
OECD PISA 데이터 기준 상위 국가의 학업 성취도 시각화

목표:
- 국가를 지구본 위에 표시
- reading, mathematics, science, composite score 비교
- 국가 간 직접 거래 관계 대신 성취도 프로파일 유사성 네트워크 표시
- 발표용으로 인상적인 데이터 저널리즘 스타일

기술 제약:
- Three.js r128
- OrbitControls 없이 pointer 이벤트로 회전
- 단일 HTML
- 외부 라이브러리는 cdnjs, jsdelivr, unpkg만

우선 mock 데이터로 첫 버전을 만들어줘.
```

### 3-2. SCORM 버전 요청 프롬프트

```text
이 시각화를 SCORM 탑재 가능한 버전으로 만들어줘.
single-SCO 구조로 가고,
imsmanifest.xml, index.html, scormdriver.js를 포함해줘.

다음 상호작용을 SCORM 상태로 추적해줘:
- 총 클릭 수
- 국가 클릭 수
- 필터/제어판 조작 수
- 타임라인 변경 수

가능하면 클릭 수를 suspend_data에 저장하고,
lesson_location에도 현재 연도와 포커스 국가를 남겨줘.
기존 시각화는 유지하고 SCORM용 패키지 폴더를 따로 만들어줘.
```

### 3-3. Web App 버전 요청 프롬프트

```text
기존 SCORM 버전은 삭제하지 말고,
이 시각화를 web deployment용 단일 HTML 버전으로 따로 만들어줘.

요구사항:
- scormdriver.js 제거
- SCORM API 호출 제거
- 상태 저장은 localStorage로 대체
- 기존 클릭 추적, 필터 상태, 타임라인 상태는 브라우저에 저장
- 단일 HTML 파일 하나만으로 배포 가능하게
```

### 3-4. 레이아웃 수정 프롬프트

```text
현재 레이아웃이 지구본 화면을 너무 침범한다.

수정 방향:
- 중앙 globe view를 먼저 확보
- 좌측은 country rail
- 우측은 controls rail
- 하단은 timeline dock
- 타이틀은 중앙 상단이지만 compact하게
- overlay가 겹쳐 보이지 않게 grid 기반으로 재구성

즉, absolute 배치 느낌보다 left rail / center stage / right rail / bottom dock 구조로 다시 잡아줘.
```

### 3-5. 시각 톤 수정 프롬프트

```text
현재 분위기가 너무 dark ambient하다.

다음처럼 바꿔줘:
- 지구 텍스처는 더 밝은 것으로
- 연결선 glow를 많이 줄이기
- 포인트 halo도 더 절제
- 전체는 premium data journalism 느낌
- 과한 sci-fi보다는 clean analytical tone
```

### 3-6. 데이터 확장 프롬프트

```text
이전 데이터를 더 포함해줘.

요구사항:
- PISA 2009, 2012, 2015, 2018, 2022를 모두 다룰 수 있게
- 연도 슬라이더는 각 cycle을 넘기게
- 각 국가는 연도별 result series를 가지게
- 모달에는 year-by-year history도 보이게
- mock historical data라도 구조가 자연스럽게 이어지게
```

## 4. 실제 협업 순서

아래 순서가 가장 안정적이다.

### Step 1. 먼저 하나의 버전만 만든다

처음부터 SCORM, 웹, Classroom, Moodle, 분석 로그, 디자인까지 한 번에 요구하지 않는다.

처음에는 이렇게 간다.

- mock data
- single HTML
- 기본 레이아웃
- 기본 인터랙션

### Step 2. 브라우저에서 본다

이 단계는 반드시 직접 한다.

확인할 것:

- 지구본이 로드되는가
- 위치가 맞는가
- 연결선이 과한가
- 타이틀이 너무 큰가
- 패널이 중앙을 침범하는가
- 모바일에서 무너지는가

### Step 3. 시각 피드백을 다시 준다

예시:

```text
so far, 잘되는 듯.
근데 layout이 안 맞는 느낌이다.
left/right panel이 center view를 너무 가린다.
타이틀도 너무 크다.
그리고 이전 데이터도 더 포함해서 연도별로 보이게 해줘.
```

### Step 4. 기능별로 잘라서 수정한다

여기서 중요한 건 피드백을 `묶지 않는 것`이다.

좋은 방식:

1. 레이아웃 수정
2. 데이터 확장
3. glow 조정
4. 영어 UI 변환
5. tracking 추가

한 번에 다 말할 수도 있지만, 정말 중요한 수정은 따로 분리하는 게 좋다.

### Step 5. 배포 형식을 분기한다

이 시점부터는 결과물을 갈라야 한다.

- `SCORM 버전`
- `웹 배포 버전`

절대 같은 파일을 계속 덮어쓰지 않는 것이 좋다.

좋은 요청 방식:

```text
기존꺼 삭제하지말고
새 폴더로 web deployment 버전을 따로 만들어줘
```

## 5. 이 프로젝트에서 실제로 유용했던 피드백 패턴

아래 피드백들은 특히 잘 먹혔다.

### 레이아웃 피드백

```text
레이아웃이 안맞는 느낌임. 다시 고려 레이아웃.
```

조금 더 좋은 버전:

```text
중앙 지구본 뷰를 먼저 살리고,
좌측/우측 패널은 rail처럼 붙고,
하단 타임라인은 별도 dock처럼 분리해줘.
현재는 overlay가 중앙을 너무 침범한다.
```

### 톤 피드백

```text
영어로 해야해.
그리고 너무 다크 앰비언트함.
밝은 지구본 텍스쳐로 하고, 연결선도 글로잉 적은 걸로
```

### 미세 수정 피드백

```text
글로잉이 아직도 심해, 톤다운 시켜 많이
```

이런 짧은 프롬프트는 매우 강력하다.  
이미 맥락이 쌓인 뒤에는 장문보다 이런 짧은 후속 지시가 더 잘 먹힌다.

### UX 피드백

```text
타이틀이 너무 큼. 폴딩할수있게 만들어
```

이런 식의 직접적 피드백은 아주 좋다.  
문제와 원하는 해결 방향이 동시에 들어 있기 때문이다.


## 8. SCORM 버전과 Web 버전을 나누는 기준

### SCORM 버전이 필요한 경우

- Moodle 같은 LMS에 업로드해야 한다
- `completion`, `score`, `resume`, `lesson_location` 같은 런타임 추적이 필요하다
- 학습활동으로서 관리해야 한다

### Web 버전이 필요한 경우

- Google Classroom에 링크로 넣고 싶다
- 일반 웹 호스팅을 하고 싶다
- SCORM 플레이어 없이 브라우저에서 바로 열고 싶다
- 단일 HTML 배포를 원한다

### 실전 권장 방식

- 시각화/앱 로직은 공유
- 저장/추적 레이어만 분기
- SCORM은 LMS용
- Web App은 링크 배포용

## 9. 브라우저에서 체크할 QA 리스트

매번 아래 순서로 보면 된다.

### 시각 QA

- 제목이 과도하게 큰가
- 패널이 중앙 뷰를 많이 침범하는가
- 색 대비가 적절한가
- glow가 너무 강한가
- 데이터가 너무 많아 복잡해 보이는가

### 상호작용 QA

- 드래그 회전이 부드러운가
- 휠 줌이 과하지 않은가
- hover tooltip이 잘 보이는가
- click modal이 정상적으로 뜨는가
- filter가 직관적인가

### 데이터 QA

- 국가 위치가 텍스처 위에서 맞는가
- 타임라인 변경 시 점수가 자연스럽게 바뀌는가
- 연도별 series가 끊기지 않는가
- top 20 정렬이 해당 연도 기준으로 바뀌는가

### 배포 QA

- SCORM zip 루트 구조가 맞는가
- 웹 버전은 단일 HTML로 바로 열리는가
- CDN 로딩 문제는 없는가

## 10. 프롬프트 작성 팁

### 짧은 후속 프롬프트가 강력하다

긴 프롬프트보다 아래 같은 짧은 프롬프트가 잘 먹힐 때가 많다.

```text
글로우 아직도 심함. 더 줄여줘
```

```text
타임라인은 더 밑으로
```

```text
모달은 덜 카드같게
```

### 이미지를 보고 말하면 더 좋다

브라우저 스크린샷을 본 뒤 이렇게 말하면 좋다.

```text
왼쪽 패널이 너무 넓어서 globe가 작아 보인다.
```

```text
타임라인 박스가 너무 앞에 나와 보인다.
```

```text
지구본보다 패널 존재감이 더 크다.
```

이건 Codex가 바로 구조 수정으로 연결하기 쉽다.

## 11. 이 프로젝트에서 저장해둘 가치가 있는 산출물

최소한 아래 네 가지는 따로 보관해두는 것이 좋다.

1. SCORM zip
2. SCORM source folder
3. Web single HTML
4. 협업 튜토리얼 문서

추천 이유:

- SCORM은 LMS용 기준본
- Web은 링크 배포용 기준본
- 튜토리얼은 다음 프로젝트 재현용

## 12. 앞으로 비슷한 프로젝트에 그대로 적용하는 방법

주제만 바꿔도 된다.

예를 들면:

- 대학 랭킹 Top 50
- 글로벌 AI 기업 네트워크
- K-POP 확산 경로
- 연구기관 국제협력 지구본
- STEM workforce migration map

그때도 구조는 같다.

1. 지구본 시각화 요구
2. 데이터 구조 정의
3. 인터랙션 정의
4. mock first
5. 브라우저 확인
6. SCORM or web branch

## 13. 마지막 조언

Codex 협업에서 가장 중요한 것은 세 가지다.

### 첫째, 결과가 아니라 단계로 시켜라

한 번에 "완벽한 결과"를 요구하지 말고:

- 첫 버전
- 시각 수정
- 데이터 수정
- 배포 분기

로 나누는 것이 훨씬 낫다.

### 둘째, 브라우저를 보고 피드백하라

시각화 프로젝트는 텍스트로만 판단하면 안 된다.  
반드시 열어보고 말해야 한다.

### 셋째, 버전을 나눠라

`기존꺼 삭제하지말고`  
이 말이 실제로 프로젝트를 살린다.

## 14. 바로 복붙 가능한 마무리 프롬프트

다음 프로젝트에서 바로 시작하고 싶다면 아래 프롬프트로 시작하면 된다.

```text
Codex와 협업해서 인터랙티브 Three.js 시각화를 만들고 싶어.

원칙:
- 먼저 작동하는 mock 버전
- 그 다음 브라우저 확인 후 시각 피드백 반영
- 기존 버전은 삭제하지 말고 분기
- 나중에 SCORM 버전과 web 단일 HTML 버전 둘 다 유지

이번 프로젝트 목표:
[여기에 주제]

우선 첫 버전을 만들어줘.
```

이 문서를 기준으로 하면, 다음에는 훨씬 빠르게 비슷한 프로젝트를 재현할 수 있다.
